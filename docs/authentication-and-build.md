# 构建、认证与启动

在 Actions 的「EasyKiosk APK 构建与验证」中点击 Run workflow 可手动构建，推送 main 也会自动触发。组件使用支持 Node24 的版本，ESLint 要求零错误。

最终分别直接上传 ARM64、x86_64 两个 .apk 文件，archive: false，不再额外打 ZIP，也不生成 SHA 文件。GitHub 页面显示的 Digest 对应每个 APK 本身，上传后会与原始 APK 的 SHA-256 进行比对。临时交接包在最终 cleanup 任务中删除；诊断保留在任务日志，不另传附件。强制取消整个运行时 cleanup 可能来不及执行，临时包自身一天过期。

未配置 EASYKIOSK_2FA_TOTP_SECRETS 或值为空时：初始管理密码为 123456，可以在设置中修改。已有自定义密码升级后保留。

配置该 Secret 后：接受一个密钥，采用 BaseToolbox 兼容的 Base32 解码：转大写，过滤非 A–Z、2–7 字符（包括忽略 8、9、分隔符和 padding），只保留完整字节并忽略不足一个字节的尾部位；解码长度仍需 16～64 字节（建议随机生成 20 字节，即 32 个标准 Base32 字符）。预检先将解码后的字节重新编码为标准 Base32，再封入 APK；Android 端采用相同规则。不要填写六位验证码、二维码链接或多个密钥。工作流最开始先校验，不合法立即失败，不开始依赖安装或内核下载。真实密钥只在最后隔离签名任务中封入 APK，构建测试任务只使用公开测试密钥。

TOTP 使用 SHA-1、六位、30 秒、前后各一个时间窗口；每个时间步只能成功使用一次。不可退回固定密码，也不能在应用里更换密钥或修改密码。更换密钥必须修改 Secret 后重新构建和安装。备份、恢复、重置和原有密码均不能改变 APK 中的模式。TOTP 包禁用 ADB 配置入口，避免首次配置路径绕过管理验证。

密码页打开时并行请求阿里云、腾讯云、百度 HTTPS 响应的时间，至少两个独立来源须在 5 秒内一致。同步完成后按单调时钟推进，90 秒后失效，每 60 秒刷新。提交验证码时只用已准备好的网络时间，不读取设备墙钟、不在点击后再联网；无可用授时时禁止提交。普通浏览器页面启动和展示不依赖授时或管理界面。

这些 HTTPS 页面不是提供 SLA 的专用授时服务，多源校验提高容错，不能承诺任何网络下一定可用。设备日期严重错误可能导致 HTTPS 证书校验失败，需要先修正系统日期；不会跳过 TLS 校验。如果设备网络统一限制出站，应允许上述域名的 HTTPS 访问。

APK 必须含有共享密钥才能离线执行 HMAC，因此拿到 APK 的人可能提取它。请保护安装包和 Secret；同一个 APK 的所有安装使用同一密钥。该模式用动态口令替换固定 PIN，不是同时要求 PIN 和 TOTP 的双因素认证。

启动优化：普通网页展台无托管启动应用时不再等待固定 3+1 秒；管理页面按进入时才加载；JS 运行时与内嵌 Chromium 并行预热，但在内核就绪前不创建 WebView。读取配置期间不显示未配置欢迎页；欢迎页仅在确认没有 URL 时出现。开机锁定保护保留，移除品牌中间屏。硬件和网页响应仍决定实际首屏时间。

中间包会在失败后也清理，因此需要重试时应选择 Re-run all jobs 或重新 Run workflow，而不是只重跑签名任务。

兼容规则来源：https://basetoolbox.com/zh/2fa/ 的公开 I()/L() 实现。过滤规则可能使不同输入得到同一密钥；请使用随机生成的标准 Base32 新密钥，避免依赖被丢弃的字符提供熵。不会猜测 String/Base64 编码，也不接受 otpauth 链接作为 Secret。

## 配置导入入口

返回自助终端下方新增「管理后台」按钮，只有点击后才展开管理登录框。默认显示选择导入配置，选择 JSON 后预览文件名、展示模式、脱敏网址、配置项数量、应用版本和导出时间，再验证当前设备密码并确认导入。TOTP 模式使用当前动态密码；文件不能替换固定密码或 TOTP 策略。

导入成功后清除管理会话并重建展台页面，重新读取配置与初始化浏览器/外部应用，无需手动重启或再点保存。设置页原有的备份恢复也在成功后直接返回展台。导出文件使用 EasyKiosk-backup-时间戳.json 命名，旧 freekiosk-backup 文件仍可导入。恢复失败不会静默忽略，部分写入失败会尝试回滚，不会显示成功。

密码页不再显示动态密码说明或授时过程文案，授时失败仅显示「网络连接失败」并可重试；输入框和确认按钮仍遵守原有联网授时、验证和锁定规则。
