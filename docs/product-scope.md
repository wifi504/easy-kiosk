# 改造范围与行为约定

状态：设计基线，未实施。

## 最终产品

easy-kiosk 只以单个 WebView 网页作为主要展示内容。首次启动直接读取 APK 中的有效预置参数，显示网页、保持常亮、应用方向与展台策略，不要求用户先填写网址或连接 Cloud。

保留管理员设置入口、PIN 校验和修改能力。进入方式默认是 1500 毫秒内点击屏幕 5 次，再输入管理员 PIN；必须保留可维护的恢复路径。新部署优先支持 Android 10、1GB 内存、16GB 存储、15.6 英寸、1080×1920 竖屏，其他设备按实机测试结果确定支持范围。

最终主界面不展示上游宣传、注册引导、外部应用启动器、Dashboard、媒体播放器、广告轮播或 Cloud 营销入口。此阶段不删除这些模块或依赖；后续先移除界面入口，再按引用与测试结果裁剪。保留网页加载恢复、开机启动和看门狗；它们不保证解除 Android 的“强行停止”，也不能直接判定网页业务是否卡死。

## 配置生命周期

- 构建时：校验环境变量，生成只读默认配置并打包。
- 首次启动：在任何设置读取、WebView 挂载或原生展台启动之前，写入完整配置并记录配置 schema 版本。写入失败不得把标记设为成功。
- 后续启动：以设备上已保存配置为准。必须按键是否存在判断，不能用真值判断覆盖 `false`、`0` 等有效值。
- 升级：同包名、同签名、递增 versionCode；保留本地配置，新增键通过显式迁移补齐。不得因构建参数变化偷偷覆盖现场网址和 PIN。
- 管理员主动恢复预置：确认后恢复当前 APK 的构建默认值；保留 Device Owner 身份，由独立操作解除。
- 清除数据或重新安装：重新应用该 APK 的构建默认值。

## “无需初始化”的边界

无需填写应用配置，不表示静默取得设备管理或其他 Android 权限。Device Owner 需在部署阶段通过 ADB 或受管设备预配设置；普通安装只能提供设备允许的展台保护。业务网页需要摄像头或麦克风时应在锁定前处理权限，不能假设打包环境变量等于系统授权。

开机自动进入网页还取决于系统广播、默认桌面与厂商 ROM。设备断电后自动上电属于硬件/固件能力。本项目不以普通 APK 承诺这些系统能力。
